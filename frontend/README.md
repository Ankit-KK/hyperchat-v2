# HyperChat v2 frontend

A new Next.js application built from scratch against the FastAPI API. No code from the legacy (Supabase-based)
frontend is copied here; the legacy app is only a reference for features and behaviour. The architecture is the
accepted PDP v2.0 Phase 1 review (decided 2026-11-25); this workspace is its Phase 2 foundation.

## Two rules that never change

- **No Supabase.** The frontend talks only to the HyperChat API: no Supabase client, no direct database access.
- **No `api.hyperchat.space` outside production.** Every development and preview build uses
  `https://api.quicktestspace.site`. The production API is set only in the production Vercel environment, at the
  final cutover. CI enforces this with `pnpm guard`, and both apps refuse to build with it unless
  `VERCEL_ENV=production`.

## Stack

|            |                                                                                        |
| ---------- | -------------------------------------------------------------------------------------- |
| Runtime    | Node 24 LTS (`.nvmrc`), pnpm 10 (`packageManager`, via corepack)                       |
| Apps       | Next.js 16 (App Router), React 19, TypeScript 5.9                                      |
| Styling    | Tailwind CSS 4 with the tokens and preset in `packages/ui`                             |
| Primitives | Radix UI (dialog, label, slot) in shadcn style                                         |
| Tests      | Vitest 4, Testing Library, MSW 2 (unit and component); Playwright scaffold in `e2e/`   |
| Lint       | ESLint 9 with typescript-eslint, jsx-a11y, react-hooks and the Next.js rules; Prettier |

Every dependency is pinned to an exact version and `pnpm-lock.yaml` is committed. `pnpm-workspace.yaml` sets
`minimumReleaseAge` to 14 days, so pnpm refuses any package version, transitive ones included, published more
recently than that. ESLint stays on 9 because `eslint-plugin-jsx-a11y` does not support ESLint 10 yet.

## Layout

```
frontend/
  openapi/openapi.json     the API's OpenAPI document (generated by backend/scripts/export_openapi.py)
  apps/web/                Next.js: public site, auth., dashboard., overlay. (routed by Host in proxy.ts)
  apps/admin/              Next.js: admin. only; strict CSP; no third-party scripts
  packages/api-client/     typed fetch client generated from openapi.json
  packages/ui/             design tokens, Tailwind preset, primitives (button, input, label, dialog, alert)
  packages/config/         shared eslint, tsconfig, prettier and vitest presets
  e2e/                     Playwright, one project per host (not run in CI yet)
  scripts/                 guard-prod-api.mjs (the production API guard) and its test
```

| ---------------------------------------------------- | ----------------------------------------------------------------------------- |
| `pnpm install`                                       | installs the workspace (CI uses `--frozen-lockfile`)                          |
| `pnpm --filter @hyperchat/web dev`                   | public, auth, dashboard and overlay hosts on port 3000                        |
| `pnpm --filter @hyperchat/admin dev`                 | admin app on port 3001                                                        |

## Environment variables

Only `*.env.example` files are committed. Copy one to `.env.local` in the same app for a local run.

| App        | Variable                   | Meaning                                                                                                        |
| ---------- | -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| web, admin | `NEXT_PUBLIC_API_BASE_URL` | API base URL, inlined at build time. Default and every non-production value: `https://api.quicktestspace.site` |
| web        | `WEB_HOST_MAP`             | optional `host=zone,...` (zones `public`, `auth`, `dashboard`, `overlay`); unset uses the built-in map below   |
| admin      | `ADMIN_HOSTS`              | optional comma-separated hosts the admin app answers on; unset uses the built-in list below                    |

## Hosts

| Production                  | Development                                 | App     | Zone                                        |
| --------------------------- | ------------------------------------------- | ------- | ------------------------------------------- |
| `hyperchat.space`           | `quicktestspace.site` (also `www.`, `app.`) | web     | public: landing and `/{slug}` creator pages |
| `auth.hyperchat.space`      | `auth.quicktestspace.site`                  | web     | auth                                        |
| `dashboard.hyperchat.space` | `dashboard.quicktestspace.site`             | web     | dashboard                                   |
| `overlay.hyperchat.space`   | `overlay.quicktestspace.site`               | web     | overlay (OBS browser sources)               |
| `admin.hyperchat.space`     | `admin.quicktestspace.site`                 | admin   | admin                                       |
| `api.` (production)         | `api.quicktestspace.site`                   | FastAPI | not a frontend                              |

How `apps/web/proxy.ts` routes (Next.js 16 renamed `middleware.ts` to `proxy.ts`):

- The `Host` header picks the zone. Unknown hosts, Vercel preview URLs included, get the public site.
- The auth, dashboard and overlay zones are rewritten to the internal segments `/auth`, `/dashboard` and `/obs`.
  Their pages live in the route groups `(auth)`, `(dashboard)` and `(overlay)`; the public pages live in `(public)`.
  The segments are reserved creator slugs, so no creator page can collide with them, and requesting one directly
  answers 404 on every host.
- Every response gets a CSP with a per-request script nonce, so every page renders dynamically. The auth,
  dashboard and overlay hosts send `X-Robots-Tag: noindex`; auth also sends `Referrer-Policy: no-referrer`. Only
  the public host can be indexed.

The admin app answers 404 on any host except its own. A `*.vercel.app` preview URL is accepted only when
`VERCEL_ENV=preview`. Its CSP allows same-origin resources, nonce scripts and no inline style attributes. It is
always `noindex, nofollow` and `no-store`.

## Authentication model

- The session is the API's `__Host-` cookie, `HttpOnly`, `SameSite=Lax`, set for the API host only. No frontend
  host ever holds or reads it. Every authenticated call is a browser request with `credentials: "include"`.
- Every POST, PUT, PATCH and DELETE sends `x-csrf-token`. The client takes the token from `POST /api/v1/auth/login`
  or `GET /api/v1/auth/session` and keeps it in memory, never in `localStorage`.
- The client never retries a request by itself. A 401 is returned as a typed result; where to send the user is
  the app's decision.
- Next.js server components make anonymous public reads only.
- Frontend route guards are user experience, never authorization.

Other principles: realtime goes through Pusher with private channels authorized by the API. Uploads go straight
to Cloudflare R2 with short-lived grants from the API. Payments use Razorpay Checkout, with orders created and
verified by the API. There is no contact form (retired, D5). The public layout shows the contact name, email,
phones and Discord invite from `GET /api/v1/public/config` and hides whatever is empty.

## Running locally against the DEV API

```bash
cd frontend
corepack enable          # once; provides the pinned pnpm
pnpm install
pnpm --filter @hyperchat/web dev      # http://localhost:3000
pnpm --filter @hyperchat/admin dev    # http://admin.localhost:3001
```

Browsers resolve `*.localhost` to your machine, so `http://auth.localhost:3000`,
`http://dashboard.localhost:3000` and `http://overlay.localhost:3000` reach the other zones. Public reads such as
the landing figures and `/{slug}` work at once, because they run on the server. Browser calls from a local origin,
such as the dashboard's session check, are refused by the API's CORS policy until that origin is on the API's
allow-list. That is a backend runtime configuration change scheduled after the PAY-15 soak (review §6 G1).

To check a production build, run `pnpm build`, then `pnpm --filter @hyperchat/web start`. Pass a `Host` header to
try each zone:

```bash
curl -I -H "Host: dashboard.quicktestspace.site" http://localhost:3000/
```

## Regenerating the API client

When a backend change alters the API:

```bash
python backend/scripts/export_openapi.py   # from the repository root; rewrites frontend/openapi/openapi.json
cd frontend && pnpm generate:api            # rewrites packages/api-client/src/schema.d.ts
```

Commit both files. The backend unit job fails while `openapi.json` is stale, and the frontend job fails while
`schema.d.ts` is stale. `GET /api/v1/auth/session` and `POST /api/v1/auth/login` return untyped objects in the
OpenAPI document, so `SignedIn` in `packages/api-client/src/client.ts` is written by hand until the backend
declares response models.

## Changing the look

`packages/ui/src/tokens.css` is the single file to replace with the owner's palette and type decision. It holds
the colour, type scale, spacing and radius variables. `packages/ui/src/preset.css` maps those variables onto
Tailwind's theme, and the components use only Tailwind classes built from them. Keep the variable names and
change the values.

## Vercel setup (owner)

Nothing here deploys. When you set up hosting:

1. Create two Vercel projects from this repository, both with the root directory `frontend`.
2. **`hyperchat-web`** uses `pnpm --filter @hyperchat/web build` with output `apps/web/.next`. Add the domains
   `quicktestspace.site`, `auth.quicktestspace.site`, `dashboard.quicktestspace.site` and
   `overlay.quicktestspace.site`. Add the `hyperchat.space` domains only at the production cutover.
3. **`hyperchat-admin`** uses `pnpm --filter @hyperchat/admin build` with output `apps/admin/.next`. Add the domain
   `admin.quicktestspace.site`.
4. Set environment variables per environment. Preview and Development get
   `NEXT_PUBLIC_API_BASE_URL=https://api.quicktestspace.site`. Production also gets the DEV API until the cutover,
   and then the production API in Production only. Set `WEB_HOST_MAP` or `ADMIN_HOSTS` only to change the built-in
   host lists.
5. Turn on Deployment Protection (Vercel Authentication) for every preview of `hyperchat-admin`. Previews of
   `hyperchat-web` serve the public zone. Vercel marks preview deployments `noindex`.
6. Node.js version: 24.x. Vercel reads pnpm from `packageManager`.
7. Before the dev hosts work end to end, the API must allow their origins. That is the post-soak backend change in
   review §6 G1-G2.
