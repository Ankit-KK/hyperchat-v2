# HyperChat v2 frontend

A new Next.js application built from scratch against the FastAPI API. No code from the legacy (Supabase-based)
frontend is copied here; the legacy app is only a reference for features and behaviour. The architecture is the
accepted PDP v2.0 Phase 1 review (decided 2026-11-25); this workspace is its Phase 2 foundation.

The marketing website is a separate repository, [hyperchat-frontend](https://github.com/Ankit-KK/hyperchat-frontend)
(Vite, its own Vercel deployment), and stays that way (owner decision R1, 2026-11-26). The two share the apex host:
see [Sharing the apex with the marketing website](#sharing-the-apex-with-the-marketing-website).

## Two rules that never change

- **No Supabase.** The frontend talks only to the HyperChat API: no Supabase client, no direct database access.
- **No `api.hyperchat.space` outside production.** Every development and preview build uses
  `https://api.quicktestspace.site`. The production API is set only in the production Vercel environment, at the
  final cutover. CI enforces this with `pnpm guard`, and both apps refuse to build with it unless
  `VERCEL_ENV=production`.

## Stack

|            |                                                                                        |
| ---------- | -------------------------------------------------------------------------------------- |
| Runtime    | Node 24 LTS (`.nvmrc`), pnpm 10 (`packageManager`, via corepack)                       |
| Apps       | Next.js 16 (App Router), React 19, TypeScript 5.9                                      |
| Styling    | Tailwind CSS 4 with the tokens and preset in `packages/ui`                             |
| Primitives | Radix UI (dialog, label, slot) in shadcn style                                         |
| Tests      | Vitest 4, Testing Library, MSW 2 (unit and component); Playwright scaffold in `e2e/`   |
| Lint       | ESLint 9 with typescript-eslint, jsx-a11y, react-hooks and the Next.js rules; Prettier |

Every dependency is pinned to an exact version and `pnpm-lock.yaml` is committed. `pnpm-workspace.yaml` sets
`minimumReleaseAge` to 14 days, so pnpm refuses any package version, transitive ones included, published more
recently than that. ESLint stays on 9 because `eslint-plugin-jsx-a11y` does not support ESLint 10 yet.

## Layout

```
frontend/
  openapi/openapi.json     the API's OpenAPI document (generated by backend/scripts/export_openapi.py)
  apps/web/                Next.js: public site, auth., dashboard., overlay. (routed by Host in proxy.ts)
  apps/admin/              Next.js: admin. only; strict CSP; no third-party scripts
  packages/api-client/     typed fetch client generated from openapi.json
  packages/ui/             design tokens, Tailwind preset, primitives (button, input, label, dialog, alert)
  packages/config/         shared eslint, tsconfig, prettier and vitest presets
  e2e/                     Playwright, one project per host (not run in CI yet)
  scripts/                 guard-prod-api.mjs (the production API guard) and its test
```

## Environment variables

Only `*.env.example` files are committed. Copy one to `.env.local` in the same app for a local run.

| App        | Variable                   | Meaning                                                                                                                                                  |
| ---------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| web, admin | `NEXT_PUBLIC_API_BASE_URL` | API base URL, inlined at build time. Default and every non-production value: `https://api.quicktestspace.site`                                           |
| web        | `MARKETING_ORIGIN`         | the marketing website's deployment, an https origin, read at build time. Required when `VERCEL_ENV=production`; unset elsewhere: `http://localhost:5174` |

## Hosts

| Production                  | Development                         | App     | Zone                                                                                  |
| --------------------------- | ----------------------------------- | ------- | ------------------------------------------------------------------------------------- |
| `hyperchat.space`           | `quicktestspace.site` (also `app.`) | web     | public: `/{slug}` creator pages; the marketing allow-list is forwarded to the website |
| `www.hyperchat.space`       | `www.quicktestspace.site`           | web     | none: 308 to the apex, path and query kept                                            |
| `auth.hyperchat.space`      | `auth.quicktestspace.site`          | web     | auth                                                                                  |
| `dashboard.hyperchat.space` | `dashboard.quicktestspace.site`     | web     | dashboard                                                                             |
| `overlay.hyperchat.space`   | `overlay.quicktestspace.site`       | web     | overlay (OBS browser sources)                                                         |
| `admin.hyperchat.space`     | `admin.quicktestspace.site`         | admin   | admin                                                                                 |
| `api.` (production)         | `api.quicktestspace.site`           | FastAPI | not a frontend                                                                        |

How `apps/web/proxy.ts` routes (Next.js 16 renamed `middleware.ts` to `proxy.ts`):

- A `www.` host is redirected permanently (308) to its https apex before anything else (owner decision R3).
- The `Host` header picks the zone. Unknown hosts, Vercel preview URLs included, get the public site, sent with
  `X-Robots-Tag: noindex`.
- The auth, dashboard and overlay zones are rewritten to the internal segments `/auth`, `/dashboard` and `/obs`.
  Their pages live in the route groups `(auth)`, `(dashboard)` and `(overlay)`; the public pages live in `(public)`.
  The segments are reserved creator slugs, so no creator page can collide with them, and requesting one directly
  answers 404 on every host.
- Every response gets a CSP with a per-request script nonce, so every page renders dynamically. The auth,
  dashboard and overlay hosts send `X-Robots-Tag: noindex`; auth also sends `Referrer-Policy: no-referrer`. Only
  the public host can be indexed.

The admin app answers 404 on any host except its own. A `*.vercel.app` preview URL is accepted only when
`VERCEL_ENV=preview`. Its CSP allows same-origin resources, nonce scripts and no inline style attributes. It is
always `noindex, nofollow` and `no-store`. Because preview URLs are accepted, Vercel deployment protection on the
admin project is required, not optional (Vercel setup, step 6).

## Authentication model

- The session is the API's `__Host-` cookie, `HttpOnly`, `SameSite=Lax`, set for the API host only. No frontend
  host ever holds or reads it. Every authenticated call is a browser request with `credentials: "include"`.
- Every POST, PUT, PATCH and DELETE sends `x-csrf-token`. The client takes the token from `POST /api/v1/auth/login`
  or `GET /api/v1/auth/session` and keeps it in memory, never in `localStorage`.
- The client never retries a request by itself. A 401 is returned as a typed result; where to send the user is
  the app's decision.
- Next.js server components make anonymous public reads only.
- Frontend route guards are user experience, never authorization.
- **The dashboard shell's session bootstrap does not work yet.** `GET /api/v1/auth/session` from
  `dashboard.quicktestspace.site` only succeeds once the backend's `browser_origins` includes that origin. That is
  the post-soak backend PR for review §6 G1. Until then the browser refuses the call (CORS) and the shell shows
  "The API could not be reached".

Other principles: realtime goes through Pusher with private channels authorized by the API. Uploads go straight
to Cloudflare R2 with short-lived grants from the API. Payments use Razorpay Checkout, with orders created and
verified by the API. There is no contact form (retired, D5). The public layout shows the contact name, email,
phones and Discord invite from `GET /api/v1/public/config` and hides whatever is empty.

## Route map (apps/web)

| Host (zone)   | Path                          | Served by                                                                             | Indexed                 |
| ------------- | ----------------------------- | ------------------------------------------------------------------------------------- | ----------------------- |
| apex (public) | marketing allow-list, `/`     | the marketing website, through the rewrites below                                     | the website's own rules |
| apex (public) | `/{slug}`                     | `app/(public)/[slug]/page.tsx`: the creator page                                      | yes, active creators    |
| apex (public) | `/{slug}/opengraph-image`     | `opengraph-image.tsx`: 1200x630 PNG from name, colour and profile picture (`next/og`) | image                   |
| apex (public) | unknown or inactive `/{slug}` | `[slug]/not-found.tsx`, status 404                                                    | no (noindex)            |
| apex (public) | `/{slug}` with the API down   | `[slug]/error.tsx`, status 500 ("temporarily unavailable")                            | no (noindex)            |
| `www.`        | any                           | 308 to the apex                                                                       | no                      |
| `auth.`       | any                           | `app/(auth)/auth/*`                                                                   | no                      |
| `dashboard.`  | any                           | `app/(dashboard)/dashboard/*`                                                         | no                      |
| `overlay.`    | any                           | `app/(overlay)/obs/*`                                                                 | no                      |

The creator page is server-rendered from `GET /api/v1/public/streamers/{slug}`, `/pricing` and `/goal` with the 60 s
revalidate in `lib/api.ts`. The page still renders per request (the root layout's `force-dynamic`, for the CSP
nonce), but those fetches stay cached: Next.js only turns `force-dynamic` into no-store for a fetch with no cache
setting of its own. Checked 2026-11-26 with `next start` against a stub API: three views of one creator page made
one call each to `/public/config`, the creator, `/pricing` and `/goal`; only successful answers are cached. The API
alone decides which creators exist: it answers 404 for unknown and non-active ones. Pricing and goal are optional;
if either call fails the page renders without that section. Images load only from absolute https URLs. A legacy
`/assets/...` path (now the website's bundle folder) or a missing image gets a placeholder.

The creator's colour (`brand_color`) is decoration only (rings, the goal bar, the Open Graph image border), never
text, and it must stay on the warm palette: `accentColor` in `[slug]/creator.ts` keeps near-greys (chroma under
15%) and colours within 45° of hue of copper (reds, oranges, ambers, browns), and uses copper for anything else
(purple, blue, green) or a malformed value. "Send an interaction" is disabled until checkout (Phase 7). Metadata is the PDP §16 template with "interactions" in the
description, canonical `https://hyperchat.space/{slug}`, Open Graph and Twitter card, and the website's Organization
JSON-LD (Streamheart Private Limited).

An App Router page cannot choose its status code, so "API unreachable" is answered with 500 rather than 503 (owner
decision 2026-11-26). Checked with `next start`: the server HTML is Next.js's error shell with
`<meta name="robots" content="noindex">` and only an error digest (no message, stack or API host); the browser then
renders `[slug]/error.tsx` ("temporarily unavailable", a retry button).

## Sharing the apex with the marketing website

The `web` app owns `hyperchat.space` (addendum §2.1 mechanism A2, owner decision R2). `apps/web/lib/marketing.ts`
holds a fixed allow-list, and `next.config.ts` forwards it with external `beforeFiles` rewrites to
`MARKETING_ORIGIN`. Everything else is this app, and other single-segment paths are creator pages.

| Forwarded               | Paths                                                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| pages                   | `/`, `/features`, `/creators`, `/company`, `/whats-new`, `/demo-signup`, `/viewer-terms`, `/support`, `/privacy-policy`, `/terms-and-conditions`, `/cancellation-refunds` |
| the website's redirects | `/feature-showcase`, `/about`, `/contact`, `/shipping`                                                                                                                    |
| files                   | `/favicon.svg`, `/third-party-notices.txt`, `/robots.txt`, `/sitemap.xml`, `/404.html`                                                                                    |
| folders, with contents  | `/legal-archive`, `/creators`, `/images`, `/intro`, `/licenses`, `/mascot`, `/partners`, `/sculpture`, `/social`, `/assets`                                               |

- Only the public zone forwards. On `auth.`, `dashboard.` and `overlay.` the proxy rewrites first, so `/features`
  there is that zone's own 404. Matching is case-insensitive, as Next.js applies the rewrites.
- The proxy sends no nonce CSP for forwarded paths: the website has an inline boot script and sets its own headers.
  Under `next start` the website's response headers pass through and the proxy's are dropped (checked 2026-11-26,
  not yet on Vercel), so the website's own `noindex` covers preview hosts.
- `/robots.txt` and `/sitemap.xml` are the website's for now, so the sitemap lists marketing pages only. Creator
  pages join it when the public creator list endpoint lands (Phase 4).
- The creator page answers 404 for any allow-listed name without asking the API. The backend reserves the same
  names in `RESERVED_SLUGS` (addendum §2.1 rule 1); a new marketing route needs that reservation first.
- For a local run, start the website's dev server on port 5174, or set `MARKETING_ORIGIN` to a deployment.
  Without either, forwarded paths fail and creator pages still work.

## Running locally against the DEV API

```bash
cd frontend
corepack enable          # once; provides the pinned pnpm
pnpm install
pnpm --filter @hyperchat/web dev      # http://localhost:3000
pnpm --filter @hyperchat/admin dev    # http://admin.localhost:3001
```

Browsers resolve `*.localhost` to your machine, so `http://auth.localhost:3000`,
`http://dashboard.localhost:3000` and `http://overlay.localhost:3000` reach the other zones. Public reads such as
the landing figures and `/{slug}` work at once, because they run on the server. Browser calls from a local origin,
such as the dashboard's session check, are refused by the API's CORS policy until that origin is on the API's
allow-list. That is a backend runtime configuration change scheduled after the PAY-15 soak (review §6 G1).

To check a production build, run `pnpm build`, then `pnpm --filter @hyperchat/web start`. Pass a `Host` header to
try each zone:

```bash
curl -I -H "Host: dashboard.quicktestspace.site" http://localhost:3000/
```

## Regenerating the API client

When a backend change alters the API:

```bash
python backend/scripts/export_openapi.py   # from the repository root; rewrites frontend/openapi/openapi.json
cd frontend && pnpm generate:api            # rewrites packages/api-client/src/schema.d.ts
```

Commit both files. The backend unit job fails while `openapi.json` is stale, and the frontend job fails while
`schema.d.ts` is stale. `GET /api/v1/auth/session` and `POST /api/v1/auth/login` return untyped objects in the
OpenAPI document, so `SignedIn` in `packages/api-client/src/client.ts` is written by hand until the backend
declares response models.

## Changing the look

`packages/ui/src/tokens.css` holds the website's palette (ivory, charcoal, copper, stone, sand; owner decision R4)
with each contrast ratio, which `tokens.test.ts` recomputes. Copper on charcoal is 4.21:1, so copper is for large
text, buttons and the focus ring, not body text. The file also holds the type scale, spacing and radius variables. `packages/ui/src/preset.css` maps those variables onto
Tailwind's theme, and the components use only Tailwind classes built from them. Keep the variable names and
change the values.

Fonts are self-hosted, so the CSP keeps `font-src 'self'`. Body text and controls use Inter Variable
(`@fontsource-variable/inter`, SIL OFL). Headings use the `HyperChat Display` alias declared in
`packages/ui/src/font-config.css`, whose `src` line is the one-line switch, as on the website.

**Display font licence (owner-accepted risk).** The display face is the website's `FastelarDemoRegular-lx4oV.ttf`,
copied unchanged (sha256 `c63702f1...effe0b`) from hyperchat-frontend `8080e5b`. No licence or provenance file
exists for it, and its name says "demo". The owner chose it for both repositories on 2026-11-26 (decision R5) and
accepted that risk. A written commercial web licence is still recommended before public launch (addendum §4.3). A
licensed replacement is a change to the `src` line in `font-config.css`.

## Vercel setup (owner)

Nothing here deploys. These steps follow Vercel's monorepo, build and package-manager docs
(vercel.com/docs/monorepos, /docs/builds/configure-a-build, /docs/package-managers). Check the first build log of
each project for the points marked "check".

1. Create two Vercel projects from this repository. Set **Root Directory** to the app folder: `frontend/apps/web`
   for `hyperchat-web` and `frontend/apps/admin` for `hyperchat-admin`. Keep **Include files outside the root
   directory in the Build Step** on, since the apps import `frontend/packages/*`.
2. Check: the first build log should show `pnpm install` resolving the whole workspace from
   `frontend/pnpm-lock.yaml`. The docs do not say this outright. If the install misses the workspace, set the
   Install Command to `cd ../.. && pnpm install --frozen-lockfile`.
3. Set `ENABLE_EXPERIMENTAL_COREPACK=1` in both projects, so Vercel uses the pnpm pinned in `packageManager`
   rather than guessing one from the lockfile. Use Node.js 24.x.
4. Domains. On `hyperchat-web`, add `quicktestspace.site`, `auth.quicktestspace.site`,
   `dashboard.quicktestspace.site` and `overlay.quicktestspace.site`. On `hyperchat-admin`, add
   `admin.quicktestspace.site`. Add the `hyperchat.space` domains only at the production cutover.
5. Environment variables per environment. Preview and Development get
   `NEXT_PUBLIC_API_BASE_URL=https://api.quicktestspace.site`. Production also gets the DEV API until the cutover,
   and then the production API in Production only. Set `WEB_HOST_MAP` or `ADMIN_HOSTS` only to change the built-in
   host lists.
6. Under Deployment Protection, turn on Vercel Authentication with Standard Protection for both projects. It
   protects every preview and generated URL, leaving only the custom domains public. Check that it is on, because
   the default is a team setting. **On `hyperchat-admin` this is mandatory:** the admin app accepts `*.vercel.app`
   hosts when `VERCEL_ENV=preview`, so an unprotected preview would serve the admin app to anyone with the URL. The apps also send `X-Robots-Tag: noindex` on every host outside their host
   lists, so `*.vercel.app` URLs are never indexed even without protection.
7. Before the dev hosts work end to end, the API must allow their origins. That is the post-soak backend change in
   review §6 G1-G2.
